vhttpd Mac 工作台 0.1.0 — 本地开发者预览

适用范围
- Apple Silicon Mac（arm64），构建目标为 macOS 15.0（Sequoia）及以上。
- CI 在 macOS 15/26 的独立 arm64 系统上验收同一下载包，具体版本与结果见包旁的验收说明。
- CI 覆盖运行与配置发布流程，不代替 Finder、原生窗口和浏览器的人工操作验收。
- Intel Mac 和实体 Mac 首次安装尚未验证；macOS 14 及以下不在当前目标范围。
- 包含 vhttpd、浏览器 Admin UI、品牌素材及所需非系统动态库。
- 内置两个 vjsx script 模板不需要安装 V、Node、npm、Homebrew 或 Xcode。
  自己导入的项目如使用其他执行器、原生扩展或外部服务，仍需其对应依赖。

安装
1. 解压 vhttpd-workbench-macos-arm64-0.1.0.zip。
2. 把整个 vhttpd-workbench.app 拖入“应用程序”或自己的“应用程序”目录。
   保留完整 .app；不要只复制包内可执行文件。无需运行安装脚本或构建命令。
3. 在 Finder 中打开应用。建议先移入固定目录，再创建或导入项目。

首次打开的系统限制
当前包仅使用 ad-hoc 签名，没有 Developer ID 签名和 Apple 公证。
下载后的隔离检查可能阻止打开；目前不能保证在其他 Mac 下载解压后直接放行。
不要为安装本预览版关闭系统安全检查，也不需要安装开发工具来解决签名问题。
如果系统阻止打开，请保留具体系统提示，先核对下载来源和 SHA256。
确认来源可信后，可由你在“系统设置 → 隐私与安全性”中针对本应用选择“仍要打开”，
并按系统提示确认；组织管理策略可能不允许该操作。这一步需要用户本人决定。
参考 Apple 说明：https://support.apple.com/102445
预览版不以签名、公证为构建前提，也不把自动化运行通过等同于系统下载放行。

第一次使用
1. 点击“新建 vjsx 项目”，选择“HTTP 入门”或“JSON API”、名称和存放目录。
   选择自己可写的普通文件夹；已有目录不会覆盖。
2. 保留“创建后立即启动，并打开浏览器 Admin UI”，点击“创建并启动”。
3. 就绪后自动在默认浏览器登录，无需复制 token；token 不放入 URL。
4. 在 Admin UI 的“项目配置”修改表单，先“保存并校验”，再“发布配置”。
   校验通过不等于已发布，已发布也不等于当前实例已生效。
5. 回到宿主点击“重启并生效”；就绪后自动检查整个项目，并重新登录 Admin UI。
   可通过“访问业务服务”核对真实业务响应。

失败与恢复
- 首次初始化可能较慢；启动最长等待 90 秒。查看宿主下方日志，不必反复创建项目。
- 端口占用、入口源码错误：修正日志中的问题后点“重新启动”。
- 实例停止超时：只有出现“强制停止”时才按需操作，仅处理本次实例进程组。
- 浏览器没有打开或登录失效：在宿主点击“打开浏览器”，无需查找 token。
- 项目目录被移动：通过“导入已有项目”选择新的 TOML 入口。
- 关闭浏览器不会停止实例；退出工作台会停止自己启动的实例。

保存与升级
- 项目源码保存在创建时选择的目录，不在 .app 包里。
- 登记与历史：~/Library/Application Support/vhttpd-workbench/
- 历史包含恢复所需的原始配置，按本机文件权限保护，不加密；界面敏感差异脱敏。
- 升级前退出工作台，替换整个 .app，保留项目目录和上述登记/历史目录。
- 没有自动更新；移除 .app 不应同时删除项目和历史，除非你确认不再需要。

第一版边界
同时管理一个本地实例；不接管外部服务。高级配置保留源码编辑。
未匹配的 HTTP 路径仍可能交给运行时默认处理器；路径匹配不等于访问限制。
不包含后台常驻、崩溃后接管、Windows/Linux 或嵌入式 WebView。
