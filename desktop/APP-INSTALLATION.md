# 独立应用安装

运行环境持有 vhttpd 进程、Admin 管理入口、共享数据库/存储、Relay 连接与私有配置。应用是代码和业务组件配置，通过主配置的 `include` 加载；多个应用共用进程、使用不同监听端口。

## Desktop 操作

首次安装支持独立应用协议的运行包且该位置没有现有环境时，Desktop 会初始化基础环境。也可在本地或远端“新建运行环境”中选择“基础运行环境（推荐）”。基础环境只创建 loopback Admin、独立管理凭据、日志/进程路径和空 include，不附带业务应用。

选中目标运行环境，进入“应用 → 安装独立应用”，选择应用目录中的 `component.toml`，填写安装目录名，先预览再确认安装。本地与 SSH 远端使用同一组件包边界。远端需要先连接 SSH，并升级到支持 `--workbench-component-version` 返回 `1` 的运行包。

可用 `examples/application-component/component.toml` 试用；它使用 vjsx 的 script profile，不需要 Node。端口和配置标识需与目标环境中的其他应用区分。

## 文件与配置边界

安装新增 `apps/<安装目录名>/` 中的代码和组件配置，仅调整主 `vhttpd.toml` 的 include 声明。已有其他配置内容、其他应用代码、数据库文件、凭据和运行包均保留。现有 include 配置参加完整校验与预览失效检查，未变更的源文件不会重新写入。

组件可声明 `listeners`、`engines`、`adapters`、`transforms`、`policies`、`pipelines` 和组件内部 include。`control`、`server`、`observability`、`resources`、`relays`、`providers` 属于环境配置，不能由组件覆盖。引擎可通过资源引用消费环境中已配置的 MySQL、存储等能力。业务监听地址和端口由组件声明，并在安装前检查冲突。

路径须限制在应用目录内，不接受符号链接和绝对路径。私有配置、`.env`、常见密钥文件、`.runtime`、日志与数据库文件不加入应用包。包限制为 64 MiB、4096 个文件、单文件 16 MiB。

首版提供新增安装；同名目录存在时拒绝覆盖，应用更新/卸载尚无独立入口。应用页只提供独立安装入口；旧整工程部署代码保留用于兼容，不作为应用安装流程。

## 生效与恢复

运行中的环境安装时会短暂停止并重启同一进程承载的全部应用，Desktop 会要求确认。新应用启动失败时恢复旧 include 和本次安装的文件，并重启原环境。外部修改或进程不能安全停止时保留现场并报告错误。停止状态的本地环境可以先安装，之后由运行环境页启动。

远端操作由脱离 SSH 会话的 helper 执行，状态和恢复材料保存在 `.desktop-deployments/<操作编号>/`；单应用安装使用自己的安装清单，不接管旧整工程清单。本地恢复针对当前 Desktop 安装操作，尚不提供 Desktop/系统崩溃后的自动续作。

## 验证进度

已通过 macOS 和 Linux 的真实进程测试：空环境持续运行、两应用依次安装、源码变化后拒绝提交、新应用启动失败恢复旧配置及原应用。已通过 Desktop 同一 SSH 代码路径的 Linux 远端验收，包括空环境初始化、独立安装、失败恢复和修复后重试。交付包与原生 Desktop 界面验收仍在执行。
