    Mac 工作台第一版验收

    2026-10-19 无证书预览包验收：通过。 CI 39177190783 从源码构建的同一个 arm64 下载包，在 macOS 15.7.9 / 26.6.2 上均通过解压搬移、新建、失败重试、跨 include 发布、宿主重启生效与历史恢复。已实际下载最终产物，SHA256 与 zip 完整性检查通过；无开发环境依赖。下载 Actions 的 workbench-macos-arm64-unsigned-verified，内含 zip、SHA256SUMS、acceptance.json 和验收说明，保留 14 天。见本轮验收元数据。

    当前按 unsigned 开发者预览交付，无需 Apple 证书。两个系统的 Gatekeeper 均返回 rejected（退出码 3）；这不是运行失败，也不是默认下载放行。Finder、目标系统窗口与浏览器首次操作未纳入此次 CI 自动化验收，受系统拦截时需由用户本人核对来源后决定是否针对该应用允许打开。安装步骤见使用说明。

    本轮冻结功能范围，按“创建 → 启动 → 自动登录 → 编辑校验 → 发布 → 待生效 → 宿主重启 → 版本恢复 → 退出重新打开”验收。结论：本机 Apple Silicon Mac 的本地开发者预览主流程已通过，保留 ui2 原生宿主与浏览器 Admin UI 的职责边界。使用步骤见Mac 工作台说明，设计见职责与范围。

    本次完整流程复验修复

    • 启动前检查失败（如端口占用）不再退回模糊的“已停止”：显示失败原因并写入运行日志，修正后直接重新启动，无需导入或创建项目。回归覆盖解除占用后复用同一项目。见进程管理与启动回归。
    • vjsx 预热失败时，管理端口仍可能连接成功。宿主识别运行程序的预热错误（包含终端颜色码），保留失败原因，等启动初始化释放资源后正常关闭本次实例，避免误报就绪或过早关闭造成收尾阻塞。真实错误入口修正后的重试由主流程回归覆盖。
    • 重启后自动重新登录 Admin UI；先处理旧实例的停止结果，再安排新实例登录，避免旧状态清除新登录请求。新增状态顺序回归，保留手动“打开浏览器”作为打开失败时的恢复入口。
    • 常用配置在原位置清楚区分“校验通过、尚未写入”“已发布、待重启生效”与操作失败，沿用品牌提示色；不增加新页面或进程控制。见配置表单。

    安装包与首次启动复验

    本次禁止读取开发目录后，旧包暴露了两处真实依赖：宿主会回读仓库的 vjsx 模板，运行程序会回读 vjsx 模块仓库的内置 JS。此前同机搬移与动态库相对路径检查不足以证明资源完全独立。

    修复为宿主和运行程序均采用生产嵌入构建；生产模式还要求显式处理现有的 Result 传播、Map 缺失分支和进程执行 API。新增交付 zip 隔离检查，在替换上一份交付物之前验证真正的压缩包。包内附有离线安装说明，并从 Mach-O 元信息生成最低系统版本。最终 zip 的解压、签名、arm64、最低系统版本、动态库相对路径与离线说明检查均通过。在全新 HOME、仅系统 PATH、禁止读取开发目录/Homebrew/V 模块及执行 Xcode 编译工具的条件下，两种内置模板的真实响应、启动失败修正重试和 32 个并发首次草稿请求均通过。未经修改的解压 .app 也通过单独的隔离启动器完成原生空列表、新建即启动、默认浏览器自动登录；真实业务请求返回 200，首次 Admin UI 加载未记录初始化 5xx。此隔离测试仍使用本机系统框架，不等同另一台干净 Mac 的验证。

    首次 Admin UI 冷启动还复现了并发创建草稿目录导致 File exists 的误报。状态目录现在逐级创建，在每一级接受其他请求刚创建的目录，仍拒绝普通文件和真实权限错误。新增多层目录并发初始化回归，并在 zip 隔离验收中增加 32 个并发首次草稿请求。实现见状态目录初始化。

    上轮构建要求 Apple Silicon、macOS 27.0；本轮兼容构建将部署目标调整为 macOS 15.0，运行验收主机仍为 macOS 27.0.1，旧系统实机结论见下文。本机分发评估返回 override=security disabled，因此无法证明默认安全设置下的下载首次打开会通过；不修改安全设置或清除隔离标记。Developer ID 签名、Apple 公证及另一台干净 Mac 的真实下载首次打开尚未完成。

    Linux 补充验证只检查了环境：共享工作树有大量既有 tracked 改动，按验证技能的停止条件保留现场；未运行 Linux 构建或测试，本轮结论不覆盖 Linux。

    最终交付包同时通过标准 ZIP UTF-8 文件名检查，包外的 安装说明.txt 可由不同解压工具正确识别。使用最终生产运行程序重跑跨 include 的监听、路由、执行器和 Adapter 新增删除、校验、发布及重启生效回归通过；隔离原生工作台正常退出后，测试端口全部释放。

    macOS 15 兼容构建复验

    最低构建目标已从 27.0 降到 15.0（Sequoia），仍仅交付 Apple Silicon arm64。原先 27.0 的来源既包括宿主和运行程序未设置部署目标，也包括本机 Homebrew 的高版本动态库；仅调整 plist 无法解决。

    构建脚本显式设置 macOS 15.0，并通过隔离依赖工具使用固定 URL 与 SHA256 的依赖锁，下载官方 arm64 Sequoia bottle 到项目 .deps，不改动系统 Homebrew。保留数据库、TLS 和 Boehm GC；GC 从源码参与兼容构建，避免隔离 pkg-config 后自动切换内存管理模式。移除 V 的 MacPorts/Intel Homebrew 回退路径，编译保持可用性诊断，链接拒绝版本等有效警告。封装与zip 检查同时拒绝最低版本高于 15.0 的二进制。反向检查确认旧 27.0 宿主被拒绝，测试代码使用 macOS 26 的 NSGlassEffectView 也被编译器拒绝。

    最终 zip 中宿主、运行程序及 11 个动态库的实际 Mach-O minos 全部为 15.0，LSMinimumSystemVersion 同步为 15.0，zip 内容与交付 App 一致。在本机 macOS 27.0.1、全新 HOME、仅系统 PATH、禁止读取开发目录/Homebrew/V 模块及执行编译工具的隔离环境下，两模板、新建登记、业务响应、失败修正重试、跨 include 发布、待生效、宿主重启、生效检查、脱敏历史比较与跨文件恢复、32 个并发首次草稿请求全部通过。使用最终包内运行程序重跑常用配置跨 include 回归也通过，覆盖 HTTP 监听、路由、vjsx 执行器、出口 Adapter 新增删除与六次实例启动。离线安装说明同步更新。

    CI 源码构建与 macOS 15/26 实际运行

    交付候选包改为由GitHub Actions从源码构建，源码测试分支不包含开发机的 App 或 zip。V、启动编译器、TCC、vjsx 和 ui2 使用固定提交；当前源码需要的依赖兼容补丁随工具链准备脚本固定。干净 CI 中修复了 V 自举时 UTF-8 locale 导致 awk 截断 C 源码的问题，并将 vjsx 补丁缩小为 ABI 与接口可见性修正，保留上游压缩资源加载函数。

    已归档的运行证据记录同一 CI 候选包在 **macOS 15.7.9（24G830）**和 **macOS 26.6.2（25G83）**两个 arm64 runner 上均通过。包 SHA256 为 3713596476fc836a76d2e1dda203e1398bab51f7cba10a96cca3cf5de0bed13f。两台 runner 都重新解压、搬移完整 App，核对签名和最低版本，再在全新 HOME、仅系统 PATH、禁止读取原用户目录、checkout、Homebrew 及执行编译工具的条件下运行宿主生产可执行文件；覆盖两个模板、新建登记、初始化失败修正重试、真实 HTTP 响应、跨 include 发布、待重启、宿主重启、整项目生效检查、脱敏版本比较与跨文件恢复。构建与独立系统运行任务全部成功，原始运行标识和日志摘要保存在上述证据文件。

    验证边界： 这是 GitHub 提供的真实目标 macOS 虚拟机自动化验证，使用宿主与管理器的原生生产可执行文件及真实实例，不包含 Finder 首次打开、GUI 控件或浏览器交互。两个系统的 spctl 策略评估都记录为 rejected，不是 Gatekeeper 首次下载放行通过；Developer ID 签名、公证及实体 Mac 默认安全设置下的完整首次安装仍待完成。macOS 14 及以下不在当前目标范围，Intel 尚未验收。

    无证书 CI 预览包验收

    当前按用户确认采用与 aidatastudio 相同的 unsigned CI 预览交付方式，不要求 Apple 证书，不以签名公证阻塞当前预览验收。工作流先从源码构建，再由 macOS 15/26 独立 runner 下载同一份 zip；两个目标系统均成功后，验收汇总核对版本、架构、包 SHA256 及 PASS 结果，生成 workbench-macos-arm64-unsigned-verified。

    统一下载产物包含安装 zip、可在下载目录直接使用的 SHA256SUMS、acceptance.json 和验收说明.txt，保留 14 天。源码仓库不包含本地编译包；任一系统失败不会生成该验收通过的下载入口。Gatekeeper 原始输出与退出码单独保留，不把 unsigned 包的策略拒绝计作运行失败，也不宣称默认下载放行。Finder、目标系统 GUI 和浏览器交互仍属于人工验收范围。具体步骤见使用说明。

    tag 发布流程接入

    源码工作流增加 vMAJOR.MINOR.PATCH 及 SemVer 预发布 tag 的触发。tag 版本统一用于 zip 文件名、App 的完整版本和离线安装说明；两个目标系统仍下载同一个源码构建包完成验收。Release 附件准备与发布随后核对包内容、版本、SHA256、源码提交与两系统结果，生成安装包、独立安装说明、覆盖全部附件的校验文件及两份验收记录。

    发布写权限只授予 tag push 后、验收汇总成功的发布任务。先上传到本流程拥有的 Draft，完成后才公开；同源码的 Draft 可重试，已有公开版本及无关 Draft 不覆盖。上传前和公开前均检查远端 tag 仍指向被验收的提交。预发布后缀映射为 GitHub Pre-release。19 项本地发布链路测试通过，包含上传失败保留 Draft、版本或源码不一致、tag 移动及已公开版本保护。工作流语法检查通过；旧版 actionlint 对已实际使用的 macos-26 标签不识别，该单项提示不影响其它表达式与权限检查。

    本轮不指定新版本或推送发布 tag，不创建实际公开 Release；完整实际上传与公开将在维护者推送实际版本 tag 时执行。具体命令与下载校验方式见发布说明。

    可选的 Developer ID 签名与公证接线

    签名与公证配置清单列出 GitHub macos-release Environment 所需的 Apple 配置。工作流增加手动 release_mode=signed：在源码构建和 macOS 15/26 运行回归通过后，依次签名包内运行程序、动态库和 App，要求公证 Accepted、装订并重新封装，随后在两个目标系统重新解压检查下载策略与整项目发布、重启生效。签名、公证或系统策略检查失败时不产生可交付的签名候选包。8 项发布链路模拟测试通过，覆盖拒绝结果、Team ID 不符、装订失败与安全策略关闭等情况。

    本轮 CI 运行 39135115917 的源码构建及 macOS 15/26 独立运行回归全部成功，普通 push 下签名公证和签名包验收任务按预期跳过。仓库尚未配置 Apple Secrets 和 macos-release Environment，真实签名、公证与签名包下载策略验收未执行；这些测试不代替实体 Mac 的浏览器下载、Finder 首次打开和原生窗口操作。本轮仅接分发链路，不增加工作台功能。

    交付范围与限制

    交付 desktop/bin/vhttpd-workbench.app，以及 desktop/bin/vhttpd-workbench-macos-arm64-0.1.0.zip。本轮验证为当前 Apple Silicon Mac，本机 .app 搬移不依赖原仓库；未执行另一台干净 Mac 或 Intel Mac 的验证。

    当前使用 ad-hoc 签名，尚未进行 Developer ID 签名和 Apple 公证，因此结论限于本地开发者预览，不称为已完成公开分发。重启后浏览器旧会话会失效；宿主就绪后自动打开默认浏览器并重新登录，自动打开失败时仍可手动点击“打开浏览器”。高级选项继续编辑来源 TOML；同时管理一个本地实例。内嵌 vjsx 的独立执行超时未采集，近期指标与慢请求样本按既定上限保留。Windows/Linux、WebView、自动更新、后台常驻和崩溃后接管不纳入本轮。

    版本历史保存恢复所需的原始配置，按本机文件权限保护，不加密；显示给用户的敏感字段差异继续脱敏。这些边界沿用现有设计，本轮未扩展新产品功能。
