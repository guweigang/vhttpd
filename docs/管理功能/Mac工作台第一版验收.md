# Mac 工作台第一版验收

本轮冻结功能范围，按“创建 → 启动 → 自动登录 → 编辑校验 → 发布 → 待生效 → 宿主重启 → 版本恢复 → 退出重新打开”验收。结论：本机 Apple Silicon Mac 的本地开发者预览主流程已通过，保留 ui2 原生宿主与浏览器 Admin UI 的职责边界。使用步骤见[Mac 工作台说明](../../desktop/README.md)，设计见[职责与范围](./本地开发工作台设计.md)。

## 本轮修复

| 问题 | 修复与证据 |
| --- | --- |
| 空项目列表首次打开白屏 | 空状态入口与侧栏使用了重复元素 ID，ui2 拒绝渲染整棵树。改为独立 ID，增加空状态说明，首次打开从创建或导入开始。见[宿主入口](../../desktop/main.v)与[元素树回归](../../desktop/ui_state_test.v)。 |
| 发布后宿主仍显示已生效，界面停止刷新 | 顶部“重启”与待生效卡片重复 ID，同样导致渲染失败。卡片改用独立操作 ID；等待、待生效和恢复等界面均校验元素树。见[状态卡片](../../desktop/config_status.v)。 |
| 从差异或恢复页重启后看不到进程进度 | 重启立即返回工作台并显示停止 / 启动进度，完成后自动检查整个项目，不需要再手动返回。见[宿主操作](../../desktop/main.v)。 |
| `.app` 依赖开发仓库位置与本机 Homebrew 动态库路径 | 应用包含运行程序、Admin UI 和 11 个当前构建的非系统动态库，使用相对加载路径并检查签名；运行程序优先从包内选择。完整包已复制到仓库外、带空格目录验证。见[构建](../../desktop/build.sh)、[封装](../../desktop/package_macos.py)和[路径选择](../../desktop/host/environment.v)。 |
| 项目登记写在开发 checkout 内，应用搬移后不方便使用 | 默认登记与历史放在用户 Application Support 目录，兼容迁移开发 checkout 的旧登记；新用户从空列表开始，模板内嵌。见[启动初始化](../../desktop/main.v)、[模板](../../desktop/host/templates.v)与[历史存储](../../desktop/host/recovery_store.v)。 |
| 通配监听地址不能直接用于浏览器访问 | `0.0.0.0` / 空地址转为本机访问地址，`::` 转为 IPv6 loopback。启动前检查主要 HTTP 业务地址的可绑定性；冲突时提示调整地址或端口，不接管其他进程。运行程序缺失与项目目录不存在分别给出操作提示。见[项目检查](../../desktop/host/project.v)、[进程管理](../../desktop/host/manager.v)与[失败回归](../../desktop/host/manager_test.v)。 |
| 使用说明还要求手动粘贴 token，并称无新建项目 | 更新为当前创建、自动登录、配置发布、生效与恢复流程，明确包的交付边界。见[使用说明](../../desktop/README.md)。 |

## 本次完整流程复验修复

- 启动前检查失败（如端口占用）不再退回模糊的“已停止”：显示失败原因并写入运行日志，修正后直接重新启动，无需导入或创建项目。回归覆盖解除占用后复用同一项目。见[进程管理](../../desktop/host/manager.v)与[启动回归](../../desktop/host/manager_test.v)。
- vjsx 预热失败时，管理端口仍可能连接成功。宿主识别运行程序的预热错误（包含终端颜色码），保留失败原因，等启动初始化释放资源后正常关闭本次实例，避免误报就绪或过早关闭造成收尾阻塞。真实错误入口修正后的重试由[主流程回归](../../desktop/smoke.v)覆盖。
- 重启后自动重新登录 Admin UI；先处理旧实例的停止结果，再安排新实例登录，避免旧状态清除新登录请求。新增[状态顺序回归](../../desktop/ui_state_test.v)，保留手动“打开浏览器”作为打开失败时的恢复入口。
- 常用配置在原位置清楚区分“校验通过、尚未写入”“已发布、待重启生效”与操作失败，沿用品牌提示色；不增加新页面或进程控制。见[配置表单](../../admin/ui/common-config-ui.js)。

## 主流程与失败场景

| 场景 | 验收结果 |
| --- | --- |
| 首次启动空列表 | 原生窗口可见创建与导入入口，无白屏。 |
| 名称非法 | 表单保留输入并提示命名规则，不生成项目。 |
| 模板与目录选择 | 原生窗口切换两种 vjsx 模板，使用系统目录选择器；含空格的项目目录可创建和启动。 |
| 创建后启动、默认浏览器自动登录 | 原生窗口显示运行中、配置已生效；默认浏览器显示“已通过工作台登录”，地址没有 token；两种模板均有真实业务响应验证。 |
| 无效端口 | Admin 表单拒绝 70000，发布按钮保持禁用；改正后可校验通过。 |
| 修改路由、发布 | 校验覆盖整个项目，发布成功显示宿主下一步；宿主自动出现项目待生效标识，差异显示 `match.paths` 前后值和来源。 |
| 宿主重启、生效 | PID 变化，状态从停止 / 启动回到运行，自动确认整项目配置已生效。 |
| 历史预览与恢复 | 原生窗口显示多个已保存版本，可预览路径字段变化并恢复，恢复后明确待重启。 |
| 退出后重新打开 | 项目登记和版本历史仍可读取；项目处于停止状态，恢复后的配置启动后确认生效并形成新历史。 |
| 跨 include 发布、版本比较与恢复 | 包内运行程序与宿主管理器真实回归通过，包含跨会话离线预览、统一恢复、再次校验、重启和新历史记录。 |
| 端口占用、重复启动、冷启动、意外退出、停止超时 | 宿主测试覆盖拒绝接管、重复启动保护、超过旧 15 秒期限的冷启动、失败提示、日志 token 脱敏、显式强制停止和进程回收。 |
| 退出清理 | 两轮原生应用退出后，四个对应业务 / 管理端口均可重新绑定；测试实例不再运行。 |

本次最终包原生窗口复验通过：从空列表创建项目，端口冲突后直接重试，选择 JSON API 模板并在含空格目录“创建并启动”，浏览器自动登录；无效端口阻止发布，修正后整项目校验发布，宿主显示待重启，点击后 PID 更新、自动确认配置一致，并自动重新登录 Admin UI。业务监听由旧端口切换到新端口后，新端口返回该项目的真实响应，旧端口已关闭。路由未匹配请求沿用运行时默认处理器，不以“旧路径必须返回 404”作为通用验收条件。相关回归及构建均针对本机 Mac，交付边界保持为本地开发者预览。

## 安装包与首次启动复验

本次禁止读取开发目录后，旧包暴露了两处真实依赖：宿主会回读仓库的 vjsx 模板，运行程序会回读 vjsx 模块仓库的内置 JS。此前同机搬移与动态库相对路径检查不足以证明资源完全独立。

修复为宿主和运行程序均采用生产嵌入构建；生产模式还要求显式处理现有的 Result 传播、Map 缺失分支和进程执行 API。新增[交付 zip 隔离检查](../../desktop/verify_macos_release.py)，在替换上一份交付物之前验证真正的压缩包。包内附有离线安装说明，并从 Mach-O 元信息生成最低系统版本。最终 zip 的解压、签名、arm64、最低系统版本、动态库相对路径与离线说明检查均通过。在全新 HOME、仅系统 PATH、禁止读取开发目录/Homebrew/V 模块及执行 Xcode 编译工具的条件下，两种内置模板的真实响应、启动失败修正重试和 32 个并发首次草稿请求均通过。未经修改的解压 `.app` 也通过单独的隔离启动器完成原生空列表、新建即启动、默认浏览器自动登录；真实业务请求返回 200，首次 Admin UI 加载未记录初始化 5xx。此隔离测试仍使用本机系统框架，不等同另一台干净 Mac 的验证。

首次 Admin UI 冷启动还复现了并发创建草稿目录导致 `File exists` 的误报。状态目录现在逐级创建，在每一级接受其他请求刚创建的目录，仍拒绝普通文件和真实权限错误。新增[多层目录并发初始化回归](../../src/admin_state_store/initialization_test.v)，并在 zip 隔离验收中增加 32 个并发首次草稿请求。实现见[状态目录初始化](../../src/admin_state_store/store.v)。

上轮构建要求 Apple Silicon、macOS 27.0；本轮兼容构建将部署目标调整为 macOS 15.0，运行验收主机仍为 macOS 27.0.1，旧系统实机结论见下文。本机分发评估返回 `override=security disabled`，因此无法证明默认安全设置下的下载首次打开会通过；不修改安全设置或清除隔离标记。Developer ID 签名、Apple 公证及另一台干净 Mac 的真实下载首次打开尚未完成。

Linux 补充验证只检查了环境：共享工作树有大量既有 tracked 改动，按验证技能的停止条件保留现场；未运行 Linux 构建或测试，本轮结论不覆盖 Linux。

最终交付包同时通过标准 ZIP UTF-8 文件名检查，包外的 `安装说明.txt` 可由不同解压工具正确识别。使用最终生产运行程序重跑跨 include 的监听、路由、执行器和 Adapter 新增删除、校验、发布及重启生效回归通过；隔离原生工作台正常退出后，测试端口全部释放。

## 交付范围与限制

交付 `desktop/bin/vhttpd-workbench.app`，以及 `desktop/bin/vhttpd-workbench-macos-arm64-0.1.0.zip`。本轮验证为当前 Apple Silicon Mac，本机 `.app` 搬移不依赖原仓库；未执行另一台干净 Mac 或 Intel Mac 的验证。

当前使用 ad-hoc 签名，尚未进行 Developer ID 签名和 Apple 公证，因此结论限于本地开发者预览，不称为已完成公开分发。重启后浏览器旧会话会失效；宿主就绪后自动打开默认浏览器并重新登录，自动打开失败时仍可手动点击“打开浏览器”。高级选项继续编辑来源 TOML；同时管理一个本地实例。内嵌 vjsx 的独立执行超时未采集，近期指标与慢请求样本按既定上限保留。Windows/Linux、WebView、自动更新、后台常驻和崩溃后接管不纳入本轮。

版本历史保存恢复所需的原始配置，按本机文件权限保护，不加密；显示给用户的敏感字段差异继续脱敏。这些边界沿用现有设计，本轮未扩展新产品功能。
