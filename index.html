开始使用

Digital Ecology Runtime

面向 PHP / TypeScript / AI 应用的高性能 Transport Runtime。
统一承载 HTTP、WebSocket、SSE、MCP 与上游流。

快速开始 → GitHub
# 一行启动 PHP 应用
$ ./vhttpd --config config/vhttpd.example.toml

# 或一行启动 TypeScript 应用
$ ./vhttpd --executor vjsx --vjsx-entry app.mts
核心特性

一个 Runtime，统一所有协议与执行模型

不再需要为 HTTP、WebSocket、SSE、MCP、AI Stream 各自搭建独立服务。 vhttpd 在协议层和业务逻辑之间提供统一的 transport runtime。

⚡

多协议接入

HTTP、WebSocket、SSE、text stream、MCP Streamable HTTP — 统一 ingress，统一调度。

🔧

多执行器模型

PHP worker 承载成熟业务，vjsx 嵌入式 TypeScript 处理快速变化的协议适配与插件逻辑。

🌊

上游流编排

原生支持 Ollama、OpenAI 等上游 token stream，自动映射为下游 SSE 或 text stream。

🤖

AI Gateway

OpenAI-compatible gateway、Ollama proxy、MCP server — 一个 runtime 全部承载。

WebSocket Upstream

飞书等长连接事件入口作为上游 provider，事件自动路由到 worker，支持 MCP 桥接。

📊

可观测运维

Admin plane 暴露 worker pool、queue、upstream sessions、MCP sessions、runtime stats。

对比优势

为什么选择 vhttpd？

传统 nginx + PHP-FPM 能工作，但面对 AI streaming、WebSocket、MCP 等现代场景时， 需要大量 infra tuning。vhttpd 为这些场景提供一等公民支持。

维度 nginx + PHP-FPM vhttpd + php-worker
Streaming 支持 可行，但需大量 infra tuning 一等公民：worker stream frames
应用 API 形态 依赖框架 / flush 特定实现 统一 StreamResponse (text / sse)
传输语义 间接通过 proxy / FPM 行为 显式 start / chunk / error / end
AI Token Streaming 通常每个项目各自实现 可复用的 runtime 模式
WebSocket 非 PHP-FPM 自然形态 原生支持 + dispatch 模式
MCP / AI Gateway 需额外服务 内置 Streamable HTTP + upstream
Worker 管理 分散在多个组件 统一 pool / queue / restart / stats
快速开始

3 分钟跑起来

从构建到运行，只需几步。支持 TOML 配置、CLI 参数、多监听器模式。

构建

# 安装依赖
make deps-core

# 构建开发版
make vhttpd

# 或构建生产版
make prod

运行

# TOML 配置（推荐）
./vhttpd --config config/vhttpd.example.toml

# 或 CLI 直接启动
./vhttpd --host 0.0.0.0 --port 19881 \
  --worker-pool-size 4 \
  --worker-autostart 1 \
  --worker-cmd 'php php-worker'

TOML 配置示例

[server]
host = "0.0.0.0"
port = 19881

[executor]
kind = "php"

[worker]
autostart = true
pool_size = 4
max_requests = 5000

[admin]
host = "127.0.0.1"
port = 19981
token = "change-me"
