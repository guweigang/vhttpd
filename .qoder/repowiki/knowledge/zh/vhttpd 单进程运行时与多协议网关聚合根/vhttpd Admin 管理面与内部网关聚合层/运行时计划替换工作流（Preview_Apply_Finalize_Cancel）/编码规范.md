- 每个操作入口函数以 `(mut app App)` 接收可变 App，并在失败路径中同时调用 `emit_*_rejected` 与 `record_runtime_plan_replacement_*` 保证审计与事件双写。
- 对共享状态 `app.replacement` 的读写一律使用 `app.mu.@lock()` / `defer { app.mu.unlock() }` 包裹，读取后立即 unlock 再执行 I/O 或外部调用以减少持锁时间。
- 错误码采用字符串常量形式（如 `'runtime_plan_replacement_no_pending'`、`'engine_not_ready'`），并通过 `status` 字段（applied/drain_ready/waiting_for_drain/rejected/cancelled）表达业务结果而非仅靠 error。
- Result 结构体包含 `config_path`、`strategy`、`error` 等公共字段，配合 `*_status_code` 辅助函数将业务状态映射为 HTTP 200/202/409。
- 需要外部副作用的操作（drain/resume/validate）采用 for 循环逐项处理，遇到第一个错误即短路返回已收集的部分结果，避免部分成功后的不一致。
