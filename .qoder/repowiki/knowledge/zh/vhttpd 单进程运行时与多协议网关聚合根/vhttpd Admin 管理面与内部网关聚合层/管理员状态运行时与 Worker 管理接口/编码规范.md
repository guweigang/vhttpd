- HTTP 端点函数统一以 `@['/path'; method]` 注解声明，并在函数体开头用 `resolve_request_id`/`resolve_trace_id` 提取追踪信息，再通过 `admin_data_plane_json_response`/`admin_data_plane_text_response` 统一包装响应。
- 对 `control_plane.admin.on_data_plane` 进行守卫检查，不在 data plane 时直接返回 404，避免在非预期进程暴露管理接口。
- 文件写入一律通过 `atomic_write`（先写 `.xxx.<micro>.tmp` 再 `os.mv` 覆盖）保证幂等与一致性，删除操作前先用 `os.exists` 判断。
- 对外暴露的 ID/namespace/key 均经过 `sanitize_segment` 或 `admin_state_safe_id` 白名单清洗，仅允许字母数字及 `-_.`，非法输入返回带前缀的错误码字符串。
- 可失败 API 返回结构化结果结构体（如 `AdminDraftValidationResult`、`AdminSourcePublishResult`、`AdminConfigFileDraftResult`），其中包含 `ok`、`error`、`draft_id` 等字段，而非直接抛错给上层。
- 每次持久化变更后通过 `store.append_event` 追加一条 JSONL 事件，并同时 `app.emit` 触发内存事件总线，形成“持久化 + 内存事件”的双通道通知模式。
