模块由三层组成：
- `provider_runtime_builder.v`：构造 `ProviderRuntimeHub`（含 `ProviderHost` 注册表 + `ProviderInstanceRegistry`），从 `ProviderRuntimeSettings` 派生各 provider 的 runtime driver/protocol/plugin/capability/hook/option 默认值，并初始化 `codex.CodexState`、`feishu.FeishuState`。
- `provider_registry.v`：声明 `pub interface Provider { init/start/stop/snapshot }`，提供 `FeishuProvider`/`CodexProvider`/`OllamaProvider`/`DbProvider` 四个薄适配结构体（仅转发到 `RuntimeContext` 闭包），并通过 `App.register_provider` / `register_provider_spec` 把实例与 `ProviderSpec` 写入 `app.providers`，所有写路径经 `App.mu.@lock()` 保护；同时暴露 `stop_all_providers` 统一调用各 runtime.stop。
- `provider_bootstrap.v`：在 `bootstrap_providers()` 中以 `$if !no_feishu_routes ? {...}` 等编译期分支按需构建具体 provider、命令处理器（`FeishuCommandHandler`/`CodexCommandHandler`/`GenericUpstreamCommandHandler`）和 `ProviderSpec`，再调用 `provider_register_and_start` 完成 init/start 并捕获错误发出 `provider.init_failed`/`provider.start_failed` 事件。
依赖方向：bootstrap → registry → runtime_builder；registry 通过 `import provider` 使用跨模块类型，不反向依赖 bootstrap。
