本模块以 `upstream/types.v` 定义的共享类型（UpstreamSendRequest、UpstreamEventSnapshot、ExecState、Io 桥接接口）为契约，把上层调度与底层传输解耦：
- `upstream_plan_delivery_projection.v` 负责把 WorkerUpstreamPlanFrame 投影成 dispatch.DeliveryOutcome，决定 stream_type/content-type/metadata，作为 plan→dispatch 的统一入口。
- `upstream_runtime.v` 的 UpstreamRuntimeContext 持有 register/unregister/note_error/emit/snapshot 回调，通过 Io 桥接 worker.WorkerHttpStreamWriter 写出 SSE/HTTP chunk，统一处理 fixture_path 与真实 HTTP 两条执行路径，并在生命周期结束时 emit http.request/http.stream.error 指标。
- `upstream_runtime_registry.v` 用 sync.Mutex 保护的 sessions map 维护活跃会话快照，供 Admin API 分页过滤查询，并把统计计数暴露给 App。
- `src/upstream/provider/{feishu,codex,ollama}` 各自实现具体协议（HTTP/WS/NDJSON），但都消费 types 中的 UpstreamSendRequest/UpstreamEventSnapshot 并通过 transport 层写回；provider 内部复用 codex/ollama 共享的 runtime/state/types。
- 跨子模块的隔离由 Io 函数指针和 UpstreamRuntimeContext 回调注入完成：transport 只依赖 upstream.transport，provider 只依赖 upstream.types + transport，runtime 通过 Io 桥接 worker 写出，三者互不直接耦合。
