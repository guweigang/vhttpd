本模块由三个同属 `module executor` 的源文件组成，围绕 InProcVjsxExecutor 扩展出两类能力：
- 插件调用层：`inproc_vjsx_plugin_runtime.v` 实现 `call_plugin_once` / `call_plugin`，负责分配 lane、确保 host 就绪、执行启动钩子、通过 `activate_lane_request_context` 注入 HTTP 调度上下文（method/path/trace_id/request_id），再以 JSON 序列化 PluginCallRequest 经 `host.call_entry(entry_kind, req_obj)` 分发到宿主侧 handler，并带重试逻辑（受 `inproc_vjsx_dispatch_retry_attempts` 控制）。
- 流式插件调用层：`inproc_vjsx_plugin_stream_runtime.v` 复用上述流程，但在得到 result 后先检测 `host.session.is_streamable_value(result)`，若可流式则通过 `host.session.stream_value` 逐帧回调 `on_frame PluginStreamFrameFn`，否则回退为普通 resolve+json_stringify；外层再包装成 `PluginStreamCallResponse{streamed, response}`。
- 响应编解码器：`inproc_vjsx_response_codec.v` 定义 `InProcVjsxResponseCodec`，其 `from_js_value` 将 vjsx.Value 解析为 `transport.WorkerResponse`——字符串直接作为 body，对象按 `{status, body, headers}` 字段映射，缺失时默认 status=200、content-type=text/plain；`headers_from_js_value` 把 headers 值以 JSON 反序列化为 map[string]string。
依赖方向单向向外：本模块仅消费上层定义的 InProcVjsxExecutor 方法、AppFacade、Lane、Host、Session、PluginCallRequest 等类型，并通过 `upstream.transport` 输出 WorkerResponse，不反向依赖上层。
