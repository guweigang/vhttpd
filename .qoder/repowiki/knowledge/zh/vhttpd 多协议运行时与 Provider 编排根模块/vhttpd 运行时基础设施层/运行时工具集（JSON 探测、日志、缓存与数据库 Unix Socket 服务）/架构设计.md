本模块由四个独立子包组成，各自以单一文件形式暴露一个 `Runtime` 结构体并通过 Unix Domain Socket 对外提供服务：
- `jsonutils`：纯函数库，实现单遍扫描的 `has_any_top_level_key`/`has_top_level_key`，仅解析顶层 key 并跳过值，避免完整 JSON 解析分配；内部复用 `unescape_json_string` 处理转义。
- `logging`：`RuntimeLogger` 通过 `VHTTPD_LOG_LEVEL` 环境变量 + `$if prod` 编译期默认值决定日志级别，调用 `log.set_logger` 替换全局 logger。
- `cachex`：`Runtime` 基于 `state_store.MemoryStateStore[string]` 实现命名空间隔离的 KV 缓存，`FrameCodec` 使用 4 字节大端长度前缀帧协议，`run()` 监听 socket 后每连接 `go handle_connection` 并发处理，`dispatch` 按 `op` 分发 get/set/patch/delete/exists/keys/ping。
- `dbx`：通过 `$if enable_db ?` 条件编译同时包含真实驱动（`db.mysql`、`db.pg`）与空桩类型，对外统一暴露 `PoolHandle`/`SessionHandle`/`QueryResult`/`ExecResult` 等接口；`ServerContext` 与 `RuntimeContext` 是闭包形式的回调接口，使 `Server.run` 循环与具体驱动解耦；MySQL 路径通过 C API (`C.mysql_fetch_fields`, `C.mysql_fetch_row`) 直接读取列名与行数据，PostgreSQL 走 `pg.DB` 池；`note_query_observation` 维护最近 50 条慢查询观察记录。
依赖方向：cachex 依赖 `state_store`，dbx 依赖 `provider`，两者均依赖 `net.unix`、`json`、`time`；logging 仅依赖标准库 `log`、`os`；jsonutils 无外部依赖。
