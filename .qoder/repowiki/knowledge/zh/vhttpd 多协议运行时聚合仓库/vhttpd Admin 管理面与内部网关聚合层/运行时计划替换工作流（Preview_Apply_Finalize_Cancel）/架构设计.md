模块按职责拆分为 8 个 `module main` 文件，围绕 App 扩展方法组织：
- `types.v` 定义所有共享结构体（`RuntimePlanReplacementRuntime`、`PendingSnapshot`、`AttemptSnapshot`、各操作 Result/Preview 等），是跨文件的唯一数据契约。
- `preview.v` 仅做 diff + execution_plan 计算，生成只读 `RuntimePlanReplacementPreview` 并通过 state 层持久化最近一次预览。
- `apply.v` 编排核心流程：校验无 pending → 加载 next plan → diff → 若需 engine_drain_required 则逐个解析 pool 并 drain，返回 draining/drain_ready；否则走 `apply_lightweight_runtime_plan` 直接热更新路由与 executor 投影。
- `finalize.v` 在 pending.ready 时调用 `prepare_runtime_plan_replacement_runtime` 构建新 engines 并原子交换到 app.engines，随后停止旧引擎。
- `cancel.v` 遍历 pending.drain_engines 反向 resume_engine 并清空 pending。
- `runtime.v` 提供 prepare/apply_prepared 两阶段：先 load+resolve+build 新 runtime 并 validate worker sockets ready，再互斥切换 app.engines 与 projection。
- `state.v` 集中维护 `app.replacement` 计数器与 last_* 快照，提供 `refresh_pending_runtime_plan_replacement` 周期性刷新 drain 状态，并提供 status_code 映射辅助 HTTP 层。
- `events.v` 封装 emit 事件名（`runtime.plan.replaced`、`...draining`、`...rejected`、`...finalize_waiting`、`...cancelled`）及 config_hash 计算。
依赖方向单向：preview/apply/finalize/cancel → state/events/runtime → types；不互相直调，统一通过 App 方法暴露边界。
