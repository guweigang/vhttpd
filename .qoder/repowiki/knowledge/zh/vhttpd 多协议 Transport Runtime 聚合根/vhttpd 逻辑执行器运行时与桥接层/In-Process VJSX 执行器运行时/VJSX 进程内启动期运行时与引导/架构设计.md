本模块围绕 `InProcVjsxExecutor` 在进程内加载 VJSX 应用的启动阶段展开，按职责拆分为五个文件：
- `inproc_vjsx_bootstrap_runtime.v`：`warmup`/`bootstrap_placeholder` 负责首次引导——校验状态、检查 lanes 与 `app_entry`、启动签名刷新协程，并将 `facade.bootstrapped` 置位。
- `inproc_vjsx_entry_resolver.v`：`InProcVjsxEntryResolver` 维护各 kind（http/websocket/plugin/startup/app_startup/snapshot/openai 等）的导出别名表与全局处理函数名映射，并提供 `module_has_callable`/`global_has_callable` 探测 JS 侧是否暴露对应入口。
- `inproc_vjsx_startup_runtime.v`：`run_lane_startup` 与 `run_app_startup` 分别按 host 索引串行执行 lane 级与应用级启动钩子；后者通过 `source_signature` 感知源码变更并在轮询中等待完成，避免重复执行。
- `inproc_vjsx_startup_hook_runtime.v`：`execute_startup_hook` 是核心编排者——构造 `InProcVjsxRuntimeMeta` 作为 runtime 对象，调用 JS 侧 `__vhttpd_create_runtime` → 入口或全局 hook → `__vhttpd_normalize_startup_result`，再将归一化后的 `commands` 经 `AppFacade.run_command_envelopes` 下发到上游。
- `inproc_vjsx_startup_codec.v`：纯数据层，定义 `InProcVjsxStartupResult` 结构及 `request_id/path/method` 生成规则，将 JS 返回的 JSON 反序列化为 `[]transport.WorkerWebSocketUpstreamCommand`。
依赖方向单向：hook_runtime 依赖 codec + entry_resolver；startup_runtime 仅依赖 hook_runtime；bootstrap 仅依赖 executor 自身 state。所有对外交互均通过 `AppFacade` 与 `VjsxExecutionLane` 抽象，不直接触碰网络 IO。
