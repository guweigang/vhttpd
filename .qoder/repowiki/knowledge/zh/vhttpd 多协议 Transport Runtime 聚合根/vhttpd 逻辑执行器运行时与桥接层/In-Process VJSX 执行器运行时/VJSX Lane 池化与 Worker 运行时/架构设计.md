本模块围绕 `InProcVjsxExecutor` 的 `state.lanes` 与 `state.lane_workers` 两个核心集合组织，形成「host 侧调度 + worker 侧执行」的两层架构：
- `inproc_vjsx_lane_pool.v`：实现轮询选择（`select_next_lane`）、按 id 选择（`select_lane_by_id`/`force_select_lane_by_id`）与超时等待（`acquire_*_lane`），通过 `inflight` 计数与 `healthy/dirty` 标记做可用性过滤，并维护 `rr_index` 做简单轮转；`release_lane` 在释放后触发 `try_schedule_websocket_mailboxes`。
- `inproc_vjsx_lane_worker_facade.v`：作为 host 到 worker 的桥接层，负责 `start_lane_workers` 启动 goroutine、将 websocket/warmup/snapshot/pump/affinity 任务投递到对应 worker 的独立 channel，并通过带 `done_ch` 与 `slot` 的 select+timeout 模式同步等待结果。
- `inproc_vjsx_lane_worker_runtime.v`：每个 lane 一个 goroutine 执行 `loop`，使用 `select` 从 `task_ch/snapshot_ch/warmup_ch/pump_ch/affinity_ch/stop_ch` 中复用读取，统一封装错误归一化与 `release_lane` defer 清理。
- `inproc_vjsx_lane_worker_task_handlers.v`：把具体业务逻辑拆成 `handle_snapshot_task/handle_warmup_task/handle_pump_task/handle_affinity_task`，由 runtime 分派调用，避免 loop 膨胀。
- `inproc_vjsx_lane_host.v`：`VjsxLaneHost` 是单个 lane 的 JS 会话宿主，封装 `session`/`module_binding` 生命周期与 `call_entry/call_global/call_handler` 等入口解析（支持默认导出与别名），供 worker 在执行阶段使用。
依赖方向单向：pool → facade → runtime → task_handlers → host，worker 通过共享 `&VjsxExecutorState` 访问 hosts/lanes，但仅以只读方式查找，写操作仍由 host 线程完成。
