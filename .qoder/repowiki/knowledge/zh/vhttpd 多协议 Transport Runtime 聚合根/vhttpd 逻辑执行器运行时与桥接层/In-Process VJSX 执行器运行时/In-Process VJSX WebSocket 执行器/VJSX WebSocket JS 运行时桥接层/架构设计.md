本模块由三个同属 `module executor` 的 V 文件组成，共同实现 InProc VJSX WebSocket 场景下宿主进程与 vjsx 引擎的双向桥接：
- `inproc_vjsx_websocket_js.v` 定义核心类型 `InProcVjsxWebSocketJs`，通过 `runtime()` 构造一个精简的 JS runtime 对象（设置 provider/executor/dispatchKind/laneId/requestId/traceId/appEntry/moduleRoot/capabilities/request 等元数据），并依据环境变量 `VHTTPD_VJSX_WS_MINIMAL_RUNTIME` 决定是否注入 `now/log/warn/error/config/getConfig/plan/getPlan` 等宿主能力；同时调用子安装函数挂载 `sessionStore` 与 `websocketDispatch`。
- `inproc_vjsx_websocket_session_store_js.v` 将 `runtime.sessionStore(namespace)` 暴露为 JS 对象，其 `get/set/delete/exists/keys` 方法通过全局宿主函数 `vhttpdHost.sessionStore` 以 JSON 编码的 `InProcVjsxHostSessionStoreRequest`/`InProcVjsxHostSessionStoreResponse` 协议进行跨语言调用。
- `inproc_vjsx_websocket_dispatch_js.v` 安装 `runtime.websocketDispatch`，把 JS 侧传入的命令数组包装成 `InProcVjsxHostWebSocketDispatchRequest`，委托给 `app.execute_websocket_dispatch_commands_result`，再把结果（含可选 close frame）序列化为 `InProcVjsxHostWebSocketDispatchResponse` 返回。
依赖方向单向向外：本模块仅依赖 `json`、`vjsx`、`upstream.transport`、`os`、`time` 以及上层 `AppFacade`/`InProcVjsxHostApi` 等已定义的类型，不反向依赖任何 JS 代码，所有跨语言边界均通过 `ctx.js_function` + `ctx.call` + JSON 序列化完成。
