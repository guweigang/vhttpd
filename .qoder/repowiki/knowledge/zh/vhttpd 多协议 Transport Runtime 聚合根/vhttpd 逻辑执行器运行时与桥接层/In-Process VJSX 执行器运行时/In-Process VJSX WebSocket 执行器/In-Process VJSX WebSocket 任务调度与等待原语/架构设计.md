本模块是 `executor` 包内针对 WebSocket 子系统的轻量支撑层，由三个文件按职责切分：
- `inproc_vjsx_websocket_types.v`：定义跨层数据载体——`InProcVjsxWebSocketFrameBundle`（原始帧 + 运行时元信息）、`InProcVjsxWebSocketTaskResult`（成功 JSON / 错误字符串）以及 `InProcVjsxWebSocketTaskSlot`（互斥保护的共享结果槽），并由 `InProcVjsxWebSocketTask` 聚合任务上下文（app facade、frame、affinity_key/actor_key、优先级、持久化标志等）。
- `inproc_vjsx_websocket_mailbox.v`：以 `InProcVjsxExecutor` 方法形式暴露邮箱 API——`enqueue_websocket_mailbox_task` 将任务按 actor_serialized 与否分别挂到 `actor_key` 或 `affinity_key` 对应的 FIFO 队列；`try_schedule_websocket_mailboxes` 作为调度循环在持有全局 `e.state.mu` 下从所有 pending key 中挑选最高优先级的队首任务，通过 `acquire_lane_by_id`（非序列化走亲和 Lane）或 `acquire_next_lane`（序列化走任意空闲 Lane）获取执行通道，再调用 `bind_websocket_task_lane` 维护 `websocket_affinity_lane_by_key` / `websocket_connection_lane_by_id` 映射，失败时把任务回退到队列并清除 running 标记；`finish_websocket_mailbox_task` 在任务完成后释放 running 状态并触发下一轮调度。
- `inproc_vjsx_websocket_task_awaiter.v`：纯无状态 Awaiter 结构体，`start` 监听 `started_ch` 并在 `inproc_vjsx_websocket_queue_wait_timeout` 后返回排队超时错误，`result` 监听 `done_ch` 并在 `inproc_vjsx_lane_task_timeout` 后返回 Lane 任务超时错误，随后读取 slot 中的 result 并校验 ready 标志。

依赖方向单向向外：types 仅依赖 `sync` 和 `upstream.transport`；mailbox 依赖 executor 自身 state 及 lane 获取 API；awaiter 不持有任何外部引用，仅消费 chan 与 slot。整个子系统围绕 `e.state` 上的互斥保护映射表完成多协程安全，并通过两个独立超时常量区分“入队等待”和“Lane 执行”两类超时。
