本模块由三个职责正交的 `.v` 文件组成，均属于 `module executor`，是 InProcVjsxExecutor 在 WebSocket 路径上的运行时扩展：
- `inproc_vjsx_websocket_event_runtime.v`：处理客户端到应用侧的 WebSocket 事件分发。`dispatch_websocket_event` 先尝试通过 `websocket_actor_enabled_for_frame` + `resolve_websocket_actor` 走 Actor 串行队列（`enqueue_websocket_mailbox_task` + `InProcVjsxWebSocketTaskAwaiter`），否则按 `resolve_websocket_dispatch_affinity` 选择是否入队或直接 `acquire_websocket_lane` 派发到指定 lane；最终经 `finalize_websocket_dispatch_response` 统一解码响应、迁移 affinity_key、释放 actor/connection 资源。
- `inproc_vjsx_websocket_upstream_runtime.v`：实现应用侧主动向上游发送消息的上行通道。`dispatch_websocket_upstream` 带重试循环（`inproc_vjsx_dispatch_retry_attempts`），每次从 `acquire_next_lane` 借 lane，构造 `WorkerWebSocketUpstreamDispatchRequest` JSON 并通过 `__vhttpd_create_runtime` / `__vhttpd_create_websocket_upstream_frame` 在 JS 端创建 runtime 和 frame，再调用入口 `websocket_upstream`，最后用 `__vhttpd_normalize_websocket_upstream_result` 归一化返回。
- `inproc_vjsx_websocket_lane_query_runtime.v`：在选定 lane 上同步运行轻量查询型入口 `websocket_affinity` 与 `websocket_actor`，分别产出 `WebSocketAffinityDecision` 与 `WebSocketActorDecision`，并拒绝异步 Promise 结果。

三者共享同一套 lane 生命周期模板：`ensure_lane_host` → `run_startup_hooks` → `activate_lane_request_context` → 调用 JS 入口 → `clear_lane_request_context` → `record_lane_success/error`；JS 对象一律显式 `defer { ...free() }` 管理内存。
