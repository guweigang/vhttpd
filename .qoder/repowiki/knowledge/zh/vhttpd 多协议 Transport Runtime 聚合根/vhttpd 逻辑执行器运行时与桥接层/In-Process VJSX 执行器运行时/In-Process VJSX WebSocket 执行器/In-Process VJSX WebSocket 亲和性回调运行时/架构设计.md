模块由三个职责清晰的 .v 文件组成，全部属于 `module executor`，围绕 `InProcVjsxExecutor` 扩展方法组织：
- `inproc_vjsx_websocket_affinity_runtime.v`：亲和性策略入口。`resolve_websocket_affinity` / `acquire_websocket_lane` / `resolve_websocket_dispatch_affinity` 三套 API 分别用于连接建立时的 lane 选择、后续帧路由以及 dispatch 阶段；当配置 `source == 'app'` 时通过 `request_lane_affinity` + `affinity_tasks` channel 把计算委派到目标 lane 上的应用代码，否则走 `WebSocketAffinityPolicy.value` 从 frame 字段提取 key。
- `inproc_vjsx_websocket_affinity_state.v`：纯状态管理。维护 `websocket_connection_*_by_id`、`websocket_affinity_lane_by_key`、`websocket_affinity_ref_count_by_key`、`websocket_mailbox_*_by_key` 等映射，并通过引用计数在最后一个连接释放时清理 affinity key 及其 mailbox，提供 `release_*` 与 `migrate_websocket_connection_affinity` 供上层调用。
- `inproc_vjsx_websocket_callback_runtime.v`：JS 回调桥接。`prepare_websocket_callback_on_lane` 负责确保 lane host 已启动、激活请求上下文并构造 `InProcVjsxWebSocketCallbackInput`；`build_payload` 优先使用宿主提供的 `__vhttpd_create_websocket_frame`（传入 `InProcVjsxWebSocketFrameBundle`），回退到 `InProcVjsxWebSocketJs.frame`；`invoke` 调用 `__vhttpd_invoke_websocket_handle`，`normalize_result` 再经 `__vhttpd_normalize_websocket_result` 将 Promise/异常归一化为 JSON 字符串返回给 transport 层。
依赖方向单向：本模块依赖 `upstream.transport`、`vjsx`、`log`、`json`，被同目录其他 executor 文件消费，不反向依赖它们。
