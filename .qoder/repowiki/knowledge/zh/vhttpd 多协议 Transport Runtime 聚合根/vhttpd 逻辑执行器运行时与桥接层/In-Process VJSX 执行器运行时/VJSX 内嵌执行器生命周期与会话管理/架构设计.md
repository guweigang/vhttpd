本模块围绕 `InProcVjsxExecutor`（定义于同目录其他文件）展开，按职责拆分为四个文件：
- `lifecycle.v`：定义跨执行器的统一抽象 `LogicExecutorLifecycle`（以函数指针替代接口，避免循环导入），并给出 disabled/php_worker/php_cgi/embedded 四种实现；其中 `embedded_executor_lifecycle` 是 VJSX 的占位实现，真正的启动/停止逻辑由 `inproc_vjsx_lifecycle.v` 通过 `new_inproc_vjsx_executor(config)` 构造。
- `inproc_vjsx_lifecycle.v`：构建 `InProcVjsxExecutor` 及其共享状态 `VjsxExecutorState`，初始化 N 个 `VjsxExecutionLane` + `VjsxLaneHost` + `VjsxLaneWorker`（每个 worker 持有 websocket/snapshot/warmup/pump/affinity/stop 多个有界 channel），并通过 `remember_app` 将 AppFacade 注入到 state 中供后续请求使用。
- `inproc_vjsx_runtime_session.v`：封装 `InProcVjsxRuntimeSessionFactory`，依据 `runtime_profile`（script/node）选择 `vjsx.runtimejs.new_script_runtime_session` 或 `new_node_runtime_session`，并附带 `InProcVjsxRuntimeProfileLog` 用于诊断日志输出；同时提供 C 回调桥接 `inproc_vjsx_runtime_session_diagnostic_handler` 以避免生成未声明的 __static__ 符号。
- `inproc_vjsx_codex_sessions.v`：提供 `CodexSessionLocator`，按环境变量优先级（`VHTTPD_CODEX_SESSIONS_ROOT` → `CODEX_HOME/sessions` → `~/.codex/sessions`）递归扫描 `.jsonl` 文件并按 thread_id 匹配，用于调试时恢复 Codex 会话。
依赖方向：本模块仅向上暴露 `InProcVjsxExecutor` 及 `LogicExecutorLifecycle` 工厂，向下依赖 `state_store`、`vjsx`、`vjsx.runtimejs`、`os`，不反向被 executor 核心以外代码直接引用。
