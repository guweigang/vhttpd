本模块是 `executor` 包内所有 VJSX 相关子模块（dispatch、snapshot、websocket、signature_refresh 等）共同依赖的“运行时内核”，按职责拆分为若干单结构体 + 方法集的文件：
- 类型与配置入口：`inproc_vjsx_types.v` 定义 `VjsxRuntimeFacadeConfig`、`VjsxExecutionLane`、`VjsxExecutorState`、`InProcVjsxExecutor`，并通过 `state_store.MemoryStateStore[string]` 持有会话；`inproc_vjsx_runtime_types.v` 定义跨进程边界的 JSON 元数据 `InProcVjsxRuntimeMeta`。
- 请求/响应载荷：`inproc_vjsx_runtime_payload.v` 将 `HttpLogicDispatchRequest` 编码为 JS 侧可读的 `WorkerHttpRequestCodec` 字符串，并组装 `InProcVjsxRuntimeMeta` 作为 `__vhttpd_create_runtime` 的参数。
- 分发主路径：`inproc_vjsx_dispatch_runtime.v` 实现 `dispatch_http`，流程为 acquire lane → ensure host → run startup hooks → activate request context → 调用 JS 全局 `__vhttpd_create_runtime` / `__vhttpd_create_ctx` → 调用 entry `http` → `__vhttpd_normalize_result` → 返回 `HttpLogicDispatchOutcome`，外层带基于 `InProcVjsxError.should_retry_dispatch` 的重试循环。
- 错误处理：`inproc_vjsx_error.v` 提供 `should_retry_dispatch`、`normalize_message`、`context_message`（从 vjsx.Context 抓取异常消息或 JSON.stringify 值）、`not_ready` 占位错误，统一以 `inproc_vjsx_executor_*` 前缀命名。
- 事件与快照：`inproc_vjsx_runtime_event.v` 负责事件 kind 标准化（补全 `vjsx.` 前缀）与 JS value→map 解析；`inproc_vjsx_snapshot_json.v` 构造 lane snapshot item 与 aggregate 根对象；`inproc_vjsx_snapshot_runtime.v` 复用 dispatch 路径注入 SNAPSHOT 请求，遍历 lanes 聚合 app/runtime 两类快照。
- 签名热刷新：`inproc_vjsx_signature_refresh.v` 启动后台 goroutine 轮询 `config.source_probe()`，在 debounce/full-refresh 阈值下计算 `source_signature()` 并写入 `VjsxExecutorState` 缓存，供外部判断是否需要重启。
- 常量：`inproc_vjsx_constants.v` 集中所有超时、重试次数、轮询间隔以及嵌入的 JS 门面源码 `$embed_file('src/inproc_vjsx_http_facade.js')`。
依赖方向单向向外：各文件仅通过 `module executor` 共享同包符号，不互相 import；对外暴露的边界是 `InProcVjsxExecutor` 方法与 `InProcVjsxRuntimeMeta` JSON 契约。
