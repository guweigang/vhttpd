本模块由四个独立的 `module main` / `module executor` 测试文件组成，分别覆盖不同边界：
- `executor_capability_interfaces_test.v`：通过一组 `accepts_*` 函数对 `executor.LogicExecutorIdentity`、`HttpLogicExecutor`、`WebSocketSessionExecutor`、`StreamLogicExecutor`、`McpLogicExecutor`、`WebSocketUpstreamExecutor`、`WebSocketEventExecutor` 等接口进行编译期约束验证，确保内置 `DisabledLogicExecutor`、`SocketWorkerExecutor`、`PhpCgiExecutor` 以及各 `logic_executor_*_port` 包装器均满足全部能力接口。
- `vjsx_host_signature_test.v`：在 `module executor` 下直接调用 `VjsxHostSignature.path_matches` 与 `expand_globs`，用临时目录 + 真实文件验证 glob 递归匹配行为，不依赖外部 OS glob 实现。
- `runtime_plan_bridge_test.v`：同样位于 `module executor`，构造完整的 `runtime_plan.RuntimePlan`（含 listener/engine/adapter/policy/pipeline），断言 `vhttpd_config_with_websocket_dispatch_policy_from_plan` 将并发策略投影为 `websocket_affinity` 与 `websocket_actor` 配置。
- `logic_executor_test.v`：最大且最核心的测试入口，使用 `App` 组合 `EngineRuntime`、`PipelineRuntime`、`ControlPlaneRuntime`、`ProtocolRuntimeHub` 等运行时结构，通过 `internal_admin_dispatch` 调用 `/admin/runtime`、`/admin/runtime/plan/replacement/*` 等内部 Admin API，覆盖 plan 替换的多种策略分支：lightweight（固定响应体/嵌入式 vjsx transform）、engine_drain_required（php-worker entry 变更触发 drain）、relay_reload_required、listener_restart_required、blocked（stateful transform 不安全切换），并校验事件日志 NDJSON 输出与 `RuntimePlanReplacementSnapshot` 状态机。

依赖方向单向向下：测试仅 import `executor`、`config`、`runtime_plan`、`admin`、`worker`、`upstream.transport` 等生产包，不引入其他测试辅助库；所有断言基于 `assert` 与 JSON 编解码，属于典型的“黑盒 + 接口契约”风格。
