本模块由三个 V 文件组成，按“选择 → 装配 → 桥接”的单向依赖组织：
- `runtime_selection.v`：定义 `ExecutorRuntimeSelection`（包含选中的 `LogicExecutor`、`WorkerBackendMode`、`LogicExecutorLifecycle`），通过 CLI `--executor` 或根据 `cfg.php`/`cfg.vjsx` 推断 kind，再查 `builtin_executor_spec_find(kind)` 调用其 `runtime_selection` 完成具体执行器的选择。
- `runtime_plan.v`：定义顶层结构体 `LogicExecutorRuntimePlan`（持有 executor、worker_backend_mode、lifecycle、bootstrap），并提供 `resolve` 入口：先委托 `ExecutorRuntimeSelection.resolve` 选出执行器，再用传入的 worker 参数构造 `ExecutorBootstrapState`，最后组装返回。
- `runtime_plan_bridge.v`：面向外部 `runtime_plan.RuntimePlan` 的适配层，提供 `resolve_from_plan` / `resolve_engine_from_plan` / `resolve_additional_engine_from_plan` 三个入口，把 plan 中的 EnginePlan 映射为 `config.VhttpdConfig`（`executor_kind_from_engine_plan`、`worker_config_from_engine_plan`、`php_config_from_engine_plan`、`vjsx_config_from_engine_plan`），并通过 `vhttpd_config_with_websocket_dispatch_policy_from_plan` + `apply_websocket_dispatch_concurrency_policy` 把 plan 中 concurrency policy 的 affinity/actor 选项注入到 `cfg.websocket_affinity` 与 `cfg.websocket_actor`；所有 plan→config 字段映射统一走 `*_option_or` 系列辅助函数（支持字符串/整型/布尔/列表/映射以及文件存在性回退）。
依赖方向：bridge → plan → selection → builtin spec → config，selection 不反向引用 bridge，保证从“静态配置/CLI”和“动态 plan”两条路径最终汇聚到同一 `LogicExecutorRuntimePlan` 产出。
