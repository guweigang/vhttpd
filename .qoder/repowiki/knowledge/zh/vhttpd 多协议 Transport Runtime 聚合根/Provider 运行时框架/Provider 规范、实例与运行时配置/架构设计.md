本模块是 `provider` 子系统的契约层，不持有具体运行时状态，仅暴露类型、配置解析与轻量存储：
- `config.v`：集中解析 `config.VhttpdConfig` 与 CLI 参数，产出只读的 `ProviderRuntimeSettings`（含 feishu/codex/bridge/db 等子配置），并提供 `normalize_runtime_driver` / `normalize_db_driver` 等归一化函数；依赖方向单向指向 `config` 与 `feishu`。
- `types.v`：声明跨模块共享的类型别名（`ProviderRouteKind`、`CommandMatcher` 等从 `command` 包 re-export）以及面向 Admin API 的快照结构体（`AdminProviderSpecSnapshot`、`AdminProviderInstanceSnapshot` 等），并给出 `ProviderInstanceSpec` 的 key 生成与字段提取方法。
- `instance.v`：以 `ProviderInstanceStore` 作为纯函数式 KV 存储（upsert/get/list），`ProviderInstanceRegistry` 只是对同一 `map[string]ProviderInstanceSpec` 的封装，按 provider 维度过滤并排序返回。
- `context.v`：通过 `RuntimeContext` 结构体携带一组闭包（snapshot/start/stop/emit），由主进程在构造每个 provider 时注入，从而让 `provider/` 反向调用 `main` 而不产生循环导入。
- `spec.v`：定义 `ProviderCommandHandler` 接口及 `NoopProviderCommandHandler` 默认实现，以及连接级指标 `ProviderRuntimeMetrics` 和启动记录 `ProviderRuntimeUpstreamLaunch`。
- `name.v`：用 `ProviderName` 对象集中提供内置 provider 名常量与默认实例名映射，避免字符串散落在各处。
依赖方向：本模块被 `server`、`admin`、`executor`、`upstream.transport` 等消费，自身仅依赖 `config`、`command`、`x.json2`、`time`、`feishu`，不反向依赖任何运行时实现。
