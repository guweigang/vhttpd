本模块由四个独立的 `module main` 文件组成，分别承担 Provider 运行时的四类入口职责：
- `provider_action_adapter_runtime.v`：解析 AdapterPlan 中的 payload/status/content_type 等选项，通过 `dispatch_provider_runtime_action_with_override` 将请求转发到具体 provider 驱动（支持 runtime_driver/runtime_plugin/capability 覆盖）。
- `provider_websocket_hook_runtime.v`：实现 handshake/normalize 两类 WebSocket Hook，按 provider 协议是否为 'websocket'/'ws' 选择对应插件与方法名，将握手帧下发或把归一化后的事件经 `dispatch_runtime_event_request` 注入运行时事件管道。
- `provider_ingress_event_runtime.v`：通用 Ingress 事件入口，填充 metadata（provider/instance/event_type/event_kind），生成 request_id/trace_id 后统一走 `dispatch_runtime_event_request`。
- `provider_instance_admin_runtime.v`：聚合持久化 spec 与静态 spec，结合上游 runtime_snapshot 拼装 `AdminProviderInstanceSnapshot` 列表，并提供 upsert 接口（JSON 反序列化 → Store.upsert → apply → 回写快照）。
依赖方向单向向外：仅依赖 `runtime_plan`、`provider`、`json`、`net.websocket`、`time` 等基础包，不反向依赖上层路由；对外暴露的函数均以 `(mut app App)` 方法形式挂载到全局 App 结构体上，由上层 HTTP 路由直接调用。
