- 每个 provider 以“薄适配 struct + 四方法实现”形式存在，init/start/stop 直接返回或委托给 `ctx.snapshot()/start()/stop()`，业务逻辑集中在 `RuntimeContext` 闭包中。
- 对共享状态（`app.providers` 的 registry/specs map）的所有读写都包裹在 `app.mu.@lock()` / `defer app.mu.unlock()` 临界区中。
- provider 注册采用“先 `register_provider(name, p)` 再 `register_provider_spec(ProviderSpec{...})`”两步模式，spec 内显式标注 `has_handler`/`has_runtime`/`route_kind`/`command_matchers`。
- 可选 provider 通过 `$if !no_xxx_routes ? { ... }` 编译期宏包裹，结合运行期 `app.provider_bootstrap_enabled(name)` 双重开关控制是否引导。
- 生命周期错误统一走 `app.emit('provider.<event>', {'name': name, 'error': err.msg()})` 上报，而非向上层传播 error。
