模块由四个文件组成，按职责分层：
- `src/server.v`（module main）是进程入口，负责 CLI 参数校验、时区初始化、SIGINT/SIGTERM 注册与子进程组清理，并通过全局 `ActiveRuntimeRegistry` 记录当前运行的 App 及其 `ServerRuntimeConfig`，在信号到达时触发统一关停。
- `src/multi_server_runtime_orchestrator.v`（module main）实现多监听器编排：根据 `MultiServerRuntimeConfig` 为每个 listener 构建独立 App，再通过 `share_websocket_listener_apps` 把 WebSocket relay delivery owner 的 app 引用复用给其他绑定，最后以并发方式启动各 listener 的 serve 循环。
- `src/server_shutdown_hooks.v`（module main）集中实现 `shutdown_app_runtime` 及 `ProcessLifecycle.stop`，按固定顺序停止引擎、关闭插件与 provider、释放缓存监听并删除 pid/admin socket 等运行时文件。
- `src/server_lifecycle/runtime_config.v` 与 `multi_config.v`（module server_lifecycle）提供纯数据/解析层：`ServerRuntimeConfig.resolve[_for_target_with_plan]` 从 plan + CLI + config 三源合并出运行时参数；`resolve_multi_server_runtime_config` 与 `resolve_plan_multi_server_runtime_config` 分别基于 `cfg.listeners` 与 `runtime_plan.RuntimePlan.listeners` 生成 `MultiServerRuntimeConfig`，并做端口重复检测与 admin 监听器归属判定。
依赖方向：server.v / multi_server_runtime_orchestrator.v → server_lifecycle.* → config / runtime_plan / executor / provider / admin；shutdown hooks 仅反向调用已构造好的 App 生命周期接口，不反向依赖 orchestrator。
