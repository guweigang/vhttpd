模块以 `command/` 子包承载纯数据与调度逻辑，`src/command_executor.v` 和 `src/command_handlers.v` 作为 main 模块中的桥接层。

- 数据与协议 (`types.v`)：定义 `CommandEnvelope`（原始信封）与 `NormalizedCommand`（归一化后字段），并通过 `from_worker_command` 把 `transport.WorkerWebSocketUpstreamCommand` 映射为统一结构；提供 `kind_for_legacy_type` 做旧类型到新 kind 的映射（如 `codex.rpc.send` → `provider.rpc.call`、`feishu.message.*` → `provider.message.*` / `stream.*`）。
- 运行时上下文 (`context.v`)：通过 `RuntimeContext` 注入闭包（`route_resolver`、`route_handler`、`instance_upsert_apply`、`instance_ensure`）以及 `Handler` 接口，使 `command/` 不直接依赖 main/provider，避免循环引用。
- 路由表 (`routing.v`)：`ProviderRouteKind` 枚举 + `CommandMatcher`（prefix/exact）描述匹配策略，供上层构造路由规则。
- 执行器 (`executor.v`)：`CommandExecutor` 是核心编排器——先给每条命令补全 trace_id/request_id，再对 `provider.instance.*` 走内置 upsert/ensure 分支，否则调用 `route_resolver` 得到 `ProviderRouteKind`，再通过 `route_handler` 取 `Handler` 执行；返回 `WebSocketUpstreamCommandActivity` 快照序列与最后错误。
- 桥接入口 (`command_executor.v`)：main 中 `build_command_context()` 用闭包捕获 App，实现 `route_resolver`（优先 codex 控制命令，再遍历 provider_specs 匹配 should_route_to_provider 与 command_matchers，默认 generic）与 `route_handler`（generic 回退到 `GenericUpstreamCommandHandler`，其余从 app.provider_enabled 查 handler 并用 `CommandHandlerAdapter` 适配成 `command.Handler`）。
- 处理器实现 (`command_handlers.v`)：`CodexCommandHandler` 处理 session.bind/clear、turn.start、rpc.send/reply；`FeishuCommandHandler` 处理 message.send/update 及 stream.append/finish/fail（含 card bridge 代理与 buffer 注册）；`GenericUpstreamCommandHandler` 处理 admin.restart_all 与通用 send/update。

依赖方向：`command/` 仅依赖 `upstream.transport`、`executor`、`log`、`time`；main 侧的 `command_executor.v` 与 `command_handlers.v` 反向依赖 `provider`、`codex`、`feishu` 等，形成“纯命令内核 + 应用桥接”的分层。
