模块按职责拆分为两层：
- 共享类型层 `src/feishu/*.v`：集中定义协议与状态结构体（`RuntimeProtoFrame`、`RuntimeEventSnapshot`、`ProviderRuntime`、`StreamBuffer`、`FeishuState`、`BridgeSettings` 等），并通过 `api.v` 暴露飞书 REST API 的 URL/Payload 构建器（发送/更新消息、上传图片、租户令牌），通过 `state.v` 以 `FeishuState` 单例统一管理多 App 的 Runtime 生命周期、事件快照、聊天聚合与 StreamBuffer 缓冲链。
- 运行时入口层（各 `_runtime.v` 文件均为 `module main`）：每个文件注册一个独立的 HTTP/WebSocket 路由或后台协程，通过 `@['/callbacks/feishu'; post]` 等注解挂载到主应用；`feishu_http_runtime.v` 提供统一的 `FeishuHttpRequest` 提取与 `feishu_json_response`/`feishu_admin_error` 响应封装，所有业务 handler 均复用该封装。

数据流向：HTTP 回调 (`feishu_callback_runtime.v`) 与 WebSocket 二进制帧 (`feishu_websocket_runtime.v`) 解析后统一写入 `FeishuState.push_event`，再经 `dispatch_feishu_provider_ingress_event` 分发至逻辑执行器；可选地走 Card Bridge 子通道（`feishu_card_bridge_client_runtime.v` 作为客户端向外部服务转发 `card.action.trigger`，`feishu_card_bridge_server_runtime.v` 接收并反向派发）。`feishu_stream_buffer_runtime.v` 在后台协程中按 400ms 周期将增量 Markdown 渲染为交互式卡片并调用 `update_message` 实现流式预览。依赖方向单向：运行时入口 → `feishu` 类型/状态 → 上层 `executor`/`upstream`/`admin` 等核心包，无循环引用。
