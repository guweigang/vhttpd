本模块按用途划分为四个并列子目录，彼此无代码依赖，仅通过环境变量和文件系统约定协作：
- `deploy/systemd/vhttpd@.service` 与 `deploy/launchd/io.guweigang.vhttpd.plist` 是系统服务模板，分别面向 systemd（带 `%i` 实例化参数）和 macOS launchd，定义运行用户、工作目录 `/var/lib/vhttpd/%i`、配置文件路径 `/etc/vhttpd/%i.toml` 及沙箱限制。
- `scripts/` 包含构建期与安装期工具：`install_ubuntu_from_source.sh` 作为主入口，依次调用 `prepare_v` / `prepare_vjsx` / `prepare_vhttpd_source` / `build_and_install_vhttpd` 完成 V 编译器、vjsx/QuickJS 与 vhttpd 源码拉取、编译与安装；`bundle_runtime_libs.sh` 基于 `ldd`/`otool` 递归收集 libmysqlclient/libpq/libssl/libgc 等依赖并改写 rpath/install_name，输出到 `runtime/libs`；其余脚本为辅助（doctor、publish、PHP 插件打包等）。
- `bench/` 以 k6 为核心，`run_host_regression.sh` 编排完整回归流程：先 build vhttpd + vslim.so，启动带 worker pool 的进程，轮询 `/bench/health` 就绪后执行 `k6_short.js` 与 `k6_stream.js`，最后 SIGINT 并校验无 php-worker 泄漏；`README.md` 统一了 `VHTTPD_*` 变量命名约定。
- `tests/e2e/` 由 `run.sh` 顺序触发 `smoke_test.sh` 与 `config_acceptance_test.sh`，前者直接调用仓库根 `./vhttpd` 二进制验证 `--help`/`--version`/未知 flag 行为。
所有脚本均为纯 bash，通过 `set -euo pipefail` 保证失败即退出，并通过 `VHTTPD_*` 前缀的环境变量进行配置注入，不引入外部语言运行时。
