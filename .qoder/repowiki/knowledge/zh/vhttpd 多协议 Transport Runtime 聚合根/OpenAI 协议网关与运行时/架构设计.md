模块按「入口 → 计划构建 → 执行器 → 响应封装」分层组织：
- 入口层 `openai_protocol_ingress_port.v` 作为 `ProtocolIngressPort` 实现，根据 `base_path` 将 `/models`、`/chat/completions`、`/responses` 及其子路径分发到各 handler；
- 协议 handler 分别位于 `openai_chat_runtime.v`、`openai_responses_runtime.v`、`openai_models_runtime.v`、`openai_planning_runtime.v`、`openai_proxy_runtime.v`、`openai_stream_proxy_runtime.v`、`openai_mapped_stream_proxy_runtime.v`、`openai_executor_once/stream/plugin_runtime.v`，统一通过 `app.openai_resolve_plan` / `resolve_responses_plan` 调用计划构建逻辑；
- 计划构建集中在 `src/api/openai/plan_builder.v`（`OpenAIResolvedPlan.validate_*` 校验链）与 `openai_plugin_planning_runtime.v`（插件 JSON → `OpenAIUpstreamPlan`），由 `openai_app_runtime.v` 中的 `openai_resolve_route` 完成 model→route→backend 的解析；
- 执行层 `OpenAIProxyRuntime` 提供 `once`/`stream`/`mapped_stream`/`executor_*` 等变体，内部再委派给 `openai_executor_once/stream/plugin_runtime.v` 以及 `openai_http_runtime_helpers.v` 的 `OpenAIRequestHeaders`/`OpenAIBackendAccess`；
- 响应封装由 `response_builder.v`（`completion_json_from_mapping`、`map_once_response`、`executor_once_body`、`responses_executor_once_body`）、`frame_mapper.v`、`chunk.v`、`helpers.v`、`path.v`、`types_runtime.v` 组成，并通过 `registry.v` 把完成的 Responses 持久化到内存状态存储；
- 类型定义集中于 `api/openai/types.v`（`OpenaiState`、`OpenAIResolvedRoute`、`OpenAIResolvedPlan`、`OpenAIPluginPlanResult` 等），所有 runtime 文件以 `module main` 暴露方法挂载到宿主 `App`，依赖方向单向：runtime → api.openai → config/state_store/net.http。
