模块由四个独立 `module main` 文件组成，分别承担不同职责并通过 `EngineRuntime` / `App` 方法与上层 Engine 组合：
- `worker_backend_connector_runtime.v`：定义 `WorkerBackendConnectorContext` 回调接口（select_socket/release/emit），封装带指数退避的 socket 选择与 `unix.connect_stream` 重试逻辑，并向上层暴露 `worker_backend_open_connection` 以返回 `worker.WorkerBackendConnection`。
- `worker_backend_pool.v`：实现按 state 维度的 worker 选择策略——优先从 `managed_workers` 中通过轮询挑选空闲且存活的实例（`lease_idle_worker_socket_for_state`），否则回退到裸 `next_worker_socket_for_state` + 探测连接；当所有 worker 处于 draining 时触发即时重启。
- `worker_backend_lifecycle_runtime.v`：负责受管 worker 的生命周期，`ensure_worker_slot_for_state` 在 slot 缺失或进程死亡时通过 `/bin/sh -lc 'exec ...'` 启动子进程并等待其 socket 就绪，使用 `transport.ManagedWorkerPool.restart_backoff_ms` 做退避；`restart_worker_slot_now_for_state` 支持主动 kill+重启，并通过 `EngineLifecyclePort.emit_fn` 上报 `worker.started/restarted/restart_scheduled` 事件。
- `worker_backend_queue.v`：基于 `ws.worker_backend.queue_capacity` 与 `queue_timeout_ms` 实现有界排队，`try_enter_state/leave_state` 用 `ws.mu` 保护计数，失败时区分 `worker queue full` 与 `worker queue timeout` 两种错误码，同时维护 `stat_queue_*_total` 指标。
依赖方向：本模块只依赖 `net.unix`、`os`、`time`、`json`、`worker` 与 `upstream.transport`，不反向依赖上层 App/Engine 的具体实现，仅通过 `EngineRuntime` 方法签名和 `EngineLifecyclePort` 回调进行松耦合集成。
