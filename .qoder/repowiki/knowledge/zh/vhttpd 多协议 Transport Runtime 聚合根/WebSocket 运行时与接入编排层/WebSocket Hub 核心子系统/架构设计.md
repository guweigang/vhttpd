模块按职责拆分为四个层次，全部属于 `ws` 包：
- 类型与状态（types.v）：集中定义 `DispatchConnState`（四态 FSM: opening/open/closing/closed）、`HubState`（连接表、房间成员、元数据、待发送队列等）及所有快照结构体，是跨文件的唯一共享契约。
- Hub 运行时（runtime.v / hub_runtime.v）：前者维护 `HubState` 的并发安全读写（`mu`/`send_mu`/`upstream_mu` 三把锁），后者通过闭包结构体 `RuntimeContext` 将具体实现与协议帧构造解耦，并暴露 `hub_send_to`、`hub_broadcast`、`hub_process_worker_frame` 等无 App 依赖的静态 API；`hub_close_target` 与 `hub_close_client` 负责关闭路径。
- 分发会话（dispatch_session.v）：对外入口 `handle_dispatch_session`，基于 `net.websocket.ServerClient` 建立本地 WS 连接，用 `DispatchBridgeState` + `DispatchConnState` 管理生命周期，消息回调经 `rt.build_frame('message'/'close')` → `rt.dispatch_event` → `rt.command_result` 进入 Worker 命令管线。
- 中继与上游（relay_agent.v / relay_carrier.v / relay_inbound.v / upstream.v / upstream_runtime.v）：`RelayAgentRuntimeContext` 封装 Agent 握手/重连/载荷处理；`relay_carrier` 作为 carrier 桥接 `relay.Runtime` 到 Hub；`upstream` 提供 fixture 模拟上游与活动记录；`upstream_runtime.v` 承载动态上游实例的生命周期。
依赖方向：上层（dispatch_session、relay_*）→ RuntimeContext 抽象 → HubState 实现；HubState 不反向依赖任何网络或 App 代码，仅通过 `RuntimeContext` 回调完成 I/O。
