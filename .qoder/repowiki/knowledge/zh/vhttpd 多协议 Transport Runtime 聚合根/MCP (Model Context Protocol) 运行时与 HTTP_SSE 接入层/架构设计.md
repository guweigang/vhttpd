模块按职责拆分为若干 `module main` 文件，通过 `app.protocols.mcp` 共享同一份 `api.mcp.protocol.McpState`（含 `sync.Mutex`、sessions map、统计量）作为唯一状态源：
- 协议类型与状态：`src/api/mcp/protocol/types.v` 定义 `Session`/`RuntimeSnapshot`/`QueueResult`/`McpState`；`state.v` 实现 session 生命周期（ensure/delete/prune/evict）、连接绑定（bind/unbind_conn）、消息队列与 flush、快照导出、origin 校验等，所有写操作均持 `s.mu`。
- 协议辅助：`helpers.v` 提供 JSON 字段级解析 `extract_client_capabilities_json` 和 SSE 帧写入 `write_sse_json`。
- HTTP 入口：`mcp_protocol_ingress_port.v` 将 `/mcp` 路由到 GET/POST/DELETE 处理函数；`mcp_runtime.v` 处理 POST（校验 method/origin/空 body → 调用 `kernel_mcp_dispatch_request` → 根据 response 决定 enqueue 或返回），`mcp_session_lifecycle_runtime.v` 处理 DELETE（按 `mcp-session-id` 删除 session 并关闭底层连接），`mcp_session_stream_runtime.v` 处理 GET（建立长连接、`takeover_conn` 后以 200ms 轮询 `flush_session` 推送 pending 消息，附带 keepalive）。
- 响应封装：`mcp_response_runtime.v` 统一构造 JSON 响应并通过 `HttpResponseRuntime.delivery_outcome` 下发；`mcp_session_delivery_projection.v` 构造 SSE delivery outcome。
- 事件投影：`mcp_exchange_projection.v` 把 worker 请求/响应/会话事件映射为 `dispatch.Exchange`（request/response/stream_open/session_message/session_close），`mcp_session_queue_runtime.v` 在入队前按 `sampling_capability_policy`（drop/error/warn）拦截 `sampling/createMessage` 并 emit 对应事件。
依赖方向：HTTP handler → `McpState` + `dispatch`/`upstream.transport`/`worker`，不反向依赖上层引擎逻辑。
