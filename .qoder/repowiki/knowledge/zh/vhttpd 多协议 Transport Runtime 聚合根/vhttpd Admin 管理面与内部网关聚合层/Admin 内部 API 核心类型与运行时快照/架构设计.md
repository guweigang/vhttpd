本模块是 admin 子系统的纯数据与工具层，不包含 HTTP 路由或监听逻辑，由上层入口（如 `src/admin/server.v`）消费：
- `types.v` 集中定义对外 JSON 响应结构体（`WorkerAdminStatus`、`WorkerPoolAdminStatus`、`AdminRestartSingleResponse` 等）、内部请求/响应载体（`InternalAdminRequest` / `InternalAdminResponse`），并提供查询参数解析（`AdminQuery.parse_boolish` / `limit` / `offset`）、Token 校验（`AdminAuth.authorized` 支持 header `x-vhttpd-admin-token` 与 query `admin_token`）、Unix socket 路径生成与标签清洗（`AdminState.default_socket*` / `sanitize_socket_label`）以及 `/admin`、`/gateway` 前缀剥离的路径归一化。
- `context.v` 通过 `RuntimeContext` 结构体暴露一组默认值为 `unsafe { nil }` 的函数指针，作为 admin 子模块访问主进程 App 状态的唯一通道，从而避免 admin 直接 import main。
- `state.v` 在 `AdminState` 方法上实现 `stats_snapshot` 与 `runtime_snapshot`，仅依赖 `RuntimeContext` 闭包从 executor、ws_hub、mcp、relay、pipeline、listener 等子系统拉取指标，组装成 `executor.AdminRuntimeStats` / `AdminRuntimeSummary` 返回给调用方。
依赖方向单向：`state.v → context.v + executor`，`types.v` 被两者共同引用；admin 子模块不持有全局状态，所有可变数据通过闭包回调间接访问。
