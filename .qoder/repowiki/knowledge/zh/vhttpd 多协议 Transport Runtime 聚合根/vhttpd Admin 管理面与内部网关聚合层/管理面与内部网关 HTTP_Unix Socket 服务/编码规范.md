- 每个 handler 先调用 `admin_plane_request(ctx, '/path')` 构造包含 path/req_id/trace_id/start_ms 的请求上下文，再走统一的认证 + 响应封装流程。
- 写操作路径统一使用 `?path=` 或 `?include_path=` 查询参数解析目标路径，读操作则从 URL 段（`:id`、`:domain`、`:kind`）提取参数。
- JSON 响应一律通过 `admin_plane_json_response` 返回，并在 metadata 中固定携带 `admin_endpoint` 与可选的 `admin_action`、`error`、`draft_id` 等键，便于观测。
- 错误分支统一返回 `json.encode(admin.AdminErrorResponse{error: ...})` 并设置对应 HTTP 状态码（400/404/422/500），成功分支返回业务结构体。
- 内部网关对二进制附件采用“先 JSON 头、后二进制 body”的两段式协议，在写入前校验 `content_length` 与实际长度一致。
