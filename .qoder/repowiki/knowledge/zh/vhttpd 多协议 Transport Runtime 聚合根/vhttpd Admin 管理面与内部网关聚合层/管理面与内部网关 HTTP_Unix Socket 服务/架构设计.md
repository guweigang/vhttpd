模块由三个独立 `module main` 文件组成，分别承担不同入口职责：
- `admin_server.v`：基于 veb 框架的 HTTP 管理服务器，定义 `AdminApp` 结构体并挂载 `/health`、`/admin/*` 系列路由（workers、stats、runtime、schema、drafts、providers、upstreams、websockets、mcp、feishu/codex/db/cache 等），所有写操作均通过 `app.shared` 反向调用主进程 App 方法；请求经 `admin_plane_request` 提取 req_id/trace_id/start_ms，再经 `admin_plane_json_response`/`admin_plane_text_response` 统一包装为带 `plane: admin` 元数据的 dispatch outcome。
- `internal_admin.v`：监听 Unix socket 的内部管理服务器，通过 `worker.WorkerBackendFrameCodec` 读写 JSON 帧，按 `mode` 分发到 `internal_admin_dispatch`（vhttpd_admin，GET 为主）或 `internal_gateway_dispatch`（vhttpd_gateway，POST，支持二进制附件如飞书图片上传），同样复用主进程 App 方法。
- `admin_data_plane_response_runtime.v`：纯响应封装库，提供 `admin_data_plane_*_response` 工具函数，将数据面处理结果以 `plane: data` 元数据注入 dispatch outcome，供数据面代码复用。
依赖方向单向：两个 server 都依赖 `admin`、`dispatch`、`json`、`time` 及主进程 `App` 暴露的管理快照方法，不反向被主进程直接引用，仅通过 `AdminPlaneRuntime.serve` / `InternalAdminRuntime.serve` 启动。
