模块由三个协作单元组成：
- `admin_state_store`（子包）：以磁盘目录为后端的 KV 持久化层，通过 `FileStore` 暴露 `get/put/delete/list` 键值操作与 append-only JSONL 事件日志；所有 namespace/key 经 `sanitize_segment` 白名单过滤，写路径使用 `.tmp` + `os.mv` 原子替换，并发由内置 `sync.Mutex` 保护。
- `admin_state_runtime.v`：定义在 `main` 模块中并挂载到宿主 `App` 方法上，作为 admin 控制面的“运行时编排器”。它组合 `config`（加载/验证 `runtime_plan`）、`admin_state_store`（持久化 draft / draft_meta / events）、`os`（include 解析、路径安全校验、TOML include 注入）和 `runtime_plan`（diff/preview），对外暴露 draft CRUD、配置/源码文件打开→草稿→发布/回滚、编译校验、diff 预览、事件拉取等能力，并通过 `app.emit` 向外部事件总线广播 `admin.draft.*`、`admin.source.published` 等事件。
- `admin_workers.v`：纯 HTTP 路由层，使用 `veb` 注解注册 `/admin/workers`、`/admin/stats`、`/admin/workers/restart`、`/admin/workers/restart/all`、`/admin/workers/drain` 五个端点，统一走 `admin_data_plane_*_response` 包装并在非 data plane 时返回 404；内部调用 `App` 上的 `worker_admin_snapshot`、`restart_worker_by_id`、`restart_all_workers`、`drain_engine` 等已实现方法，不直接访问文件系统。
依赖方向：`admin_workers.v` → `admin`（共享响应封装/事件发射）→ `App` 方法；`admin_state_runtime.v` → `admin_state_store` + `config` + `runtime_plan` + `os` + `json` + `time`；`admin_state_store` 仅依赖标准库，是单向底层。
