模块按职责拆分为三层：
- 协议层 `src/codex/`（纯 V module）：`types.v` 定义 `ProviderRuntime`、`CodexState`、`PendingRpc`、`ReadFallback` 等核心结构；`rpc.v` 提供零分配 JSON-RPC 分类器 `RpcFrame.classify`、轻量字段提取器 `RpcField.string/raw/thread_id`、`SandboxMode.format` 以及 `WebSocketHeartbeat.ping_loop`；`runtime.v` 与 `state.v` 暴露 `ProviderRuntime` 的状态机方法（begin_turn_stream / bind_stream_to_thread / schedule_read_fallback / queue_error_burst 等）和实例多租户存取（`CodexState.snapshot/update` + `sync.Mutex`）。
- 接入层（`module main` 的独立 .v 文件）：每个文件对应一个处理面——`codex_rpc_runtime.v` 是文本帧入口，按 `classify` 结果分派到 response/notification/request；`codex_rpc_request_runtime.v` 把服务端发起的请求经 `kernel_websocket_upstream_dispatch_request` 转发给 PHP worker；`codex_rpc_response_runtime.v` 通过 `pending_rpcs[id]` 反查 stream/message_id 并派发回 PHP；`codex_notification_runtime.v` 拦截 `thread/status/changed` 与 `error` 通知走错误聚合路径；`codex_rpc_send_runtime.v` 封装 `codex_send_rpc`/`codex_reply_rpc` 供上层调用；`codex_turn_runtime.v` 实现 `turn/start` 参数拼装与错误风暴合并（500ms 窗口 + `err_bursts`）。所有 handler 均通过 `app.kernel_websocket_upstream_dispatch_request` 将原始 JSON 推入上游逻辑执行器，保持“网关只路由不解析”的边界。
- 连接层 `codex_provider_websocket_runtime.v`：实现 `upstream.UpstreamSendRequest` 接口，并在 `codex_post_connect_handshake` 中顺序发送 initialize → initialized → thread/start，随后 `attach_connection` 保存 `ws.Client`。
依赖方向严格单向：接入层 → codex module 类型/状态 → upstream 抽象，反向无引用。
