- 每个处理分支都返回结构化的 Outcome 枚举+结构体（`ForwardingOutcome` / `InboundOutcome` / `OutboundOutcome`），错误通过 `error` 字段而非 panic 表达。
- 失败路径统一使用 `or { return ... }` 模式，并在 `forwarding_rejected` 等辅助函数中集中填充 `action=.rejected` 及 trace/frame 元信息。
- 通道定位遵循“显式 channel_id 优先，correlation_id 回退”的两级解析策略，由 `resolve_forward_channel_id` 封装复用。
- 事件追踪字段通过 `event_fields` 与 `*_event_fields` 辅助函数构造，并以 `relay_event = '<direction>.<action>'` 形式写入 fields map。
