- 每个 transport 事件类型都成对提供 `_request` 工厂方法与同名 `_method` 调用方法（如 `kernel_stream_dispatch_open_request` + `kernel_stream_dispatch_open`），前者只构造请求体，后者再委托给核心分发器。
- 上下文构造采用 `from_xxx` 与 `from_xxx_provider(req, provider)` 双工厂模式，后者显式传入 `logic_executor_provider()` 以区分不同 worker 后端。
- 所有 map/slice 字段在构造 transport 请求时一律 `.clone()`，避免共享可变状态跨进程传递。
- 能力校验通过布尔位域 `Capabilities` 配合 `capabilities_satisfy` / `missing_capabilities` 工具函数进行，而非手写 if 链。
