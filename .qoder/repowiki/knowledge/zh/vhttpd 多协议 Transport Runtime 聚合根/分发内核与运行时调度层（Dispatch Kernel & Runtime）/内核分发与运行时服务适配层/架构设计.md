本模块是 `upstream.transport` 到 `executor`/`engines` 之间的适配层，按职责拆分为五个子文件：
- `kernel_dispatch.v`（main 模块）：作为对外入口，把 `App` 的方法包装成 `transport.StreamDispatchRequest` / `WorkerMcpDispatchRequest` / `WorkerWebSocketUpstreamDispatchRequest` / `WorkerWebSocketFrame` 的处理器，并在 MCP/WebSocket upstream 路径中额外执行命令快照；错误通过 `KernelDispatchFailureMapper` 映射回 `executor.KernelStreamDispatchFailure`。
- `dispatch/kernel.v`：纯函数工厂，负责构造上述 transport 请求结构体以及解析 stream 错误，屏蔽 `transport` 包内部字段差异。
- `dispatch/context.v`：提供从各 transport 请求构造 `executor.DispatchContext` 的工厂方法，统一注入 session、payload、metadata 和 event 字段。
- `dispatch/pipeline.v`：定义 Pipeline/Transform/Terminal 描述符及 `PipelineDispatcher` 接口，并通过 `capabilities_satisfy` / `missing_capabilities` 实现 ingress 与 pipeline 的能力匹配校验。
- `dispatch/runtime_services.v`：暴露 `RuntimeServices` 接口的 `NoOp` 空实现，供测试或无追踪场景使用。
- `dispatch/relay.v`：将外部 relay 帧转换为内部 `Exchange`，补齐 protocol/relay_id/carrier_id 等元数据。
- `dispatch_context.v`（main 模块）：在 `main` 命名空间下对 `dispatch.dispatch_context_from_*` 做一层别名转发，使上层以 `DispatchContext.from_xxx(...)` 风格调用。
依赖方向单向：`kernel_dispatch.v` → `dispatch/*` → `executor` / `upstream.transport`，本模块不直接持有引擎实例，仅通过 `app.engines.*` 回调完成实际分发。
